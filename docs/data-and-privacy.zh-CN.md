# 数据口径与隐私

[English](data-and-privacy.md) · [README](../README.zh-CN.md)

## 数据来源与覆盖范围

应用读取指定 Codex 数据目录下的 `state_*.sqlite` 会话索引、可选的 `thread_history_*.sqlite` 历史数据库，以及 JSONL 会话日志。每类数据库选择编号最新的文件。这些格式属于 Codex 实现细节，不是稳定的公共 API 契约。

目录覆盖本机索引中的全部会话，包括归档和系统任务。筛选影响界面展示，不限制采集器可以观察的范围。日志处理有队列与单批预算，历史和上下文材料采用增量或按需加载。目录完整不等于已经读取所有历史正文。

源 SQLite 连接以只读方式打开，并设置 `query_only=ON`。应用不写源会话、不改 Codex 配置、不恢复任务、不发送提示、不调用模型。标题缺失时，可能启动本机安装的 `codex app-server`，通过仅查询状态数据库的 `thread/list` 补全名称，并关闭该子进程中的插件与应用功能。应用无法控制已安装 Codex 二进制的所有内部行为。

## 缓存与网络行为

- 默认数据目录：`CODEX_HOME`，未设置时为 `~/.codex`。
- 默认缓存：`~/Library/Application Support/CodexAgentMonitor`，可用 `CODEX_MONITOR_CACHE` 指定。
- 缓存包含检查点、有限事件摘要、上下文及用量采样、去重信息和已看标记。它不是所有源正文的完整副本，但摘要仍可能包含敏感文字，应按源数据同等保护。
- 监控期用量最多保留 30 天，不重建全历史账单。
- 监控器不含遥测客户端、远程同步或会话内容上传路径。用户下载安装时会访问 GitHub；打开原任务调用本地 Codex URL handler。macOS 可能执行自身的应用安全检查。
- 系统通知由用户选择启用，通知正文使用通用提示，不复制任务或工具正文。

## 数字与状态的边界

| 观察项 | 可以这样理解 | 不能这样理解 |
| --- | --- | --- |
| 最后事件、最新轮次状态 | 从兼容的持久化来源获得的最近证据 | 权威实时进程心跳 |
| 最近活跃 | 轮次未结束，近 5 分钟有执行或开始记录 | 覆盖所有活跃进程或云端活动 |
| 状态待确认 | 最后记录为运行中，但时效证据不足 | 已确认卡死、停止或完成 |
| 上下文采样 | 某个时间点记录的用量与容量 | 每次模型请求的精确完整正文 |
| 已记录文本占比 | 分类后的可读字符相对体积 | 每条消息、每个 Skill 的精确 Token 成本 |
| 压缩替换内容 | 替换消息集合中确实记录了哪些材料 | 所有旧内容都在压缩后保留 |
| 不可读摘要 | 能确认摘要存在，但无法读正文 | 上下文为空或消耗为零 |
| 工具输出体积 | 已记录可见文本的大小 | 当前上下文仍保留的 Token |
| 监控期用量 | 采集器已观察并归属的用量 | 供应商账单或全历史精确费用 |

源数据读取失败时，应用保留已有观察结果并提示异常。未知值与不完整历史会明确展示。较新的兼容生命周期证据可以覆盖较旧状态；一次工具失败不会自动把整个任务判为失败。

## 分享诊断信息

优先使用合成数据。任务标题、项目路径、提示、工具结果、截图、标识和缓存都可能暴露私有工作内容。提交 Issue 前应检查并脱敏。`MonitorProbe` 输出数量、耗时和诊断信息，不输出任务标题或工具正文，但分享前仍需检查。[安全说明](../SECURITY.md)
