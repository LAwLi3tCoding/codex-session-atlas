# 全会话轨迹与上下文监控设计

版本：0.3.0。适用于本机 Codex 的持久化会话。本文描述可运行版本的实现、数据口径和恢复边界。

## 目标与使用方式

在独立 macOS 窗口中持续发现本机全部项目的会话及子 Agent，帮助使用者发现需要处理的任务、定位相关事件、解释上下文变化。窗口选择与采集范围分离。关闭窗口不退出采集，退出应用停止采集，重新启动后从检查点补读。

界面分为任务列表和详情两栏，项目放入筛选菜单，避免重复导航。详情使用「概览、上下文、轨迹、协作」四个入口。概览优先回答最近在做什么、上下文余量及待处理事项；窄窗口使用列表与详情切换。历史目录全量读取，详情按需加载。系统任务默认不展示，但仍参与采集。

视觉采用浅灰侧栏、白色内容区和中性导航。颜色主要区分材料类别；正文使用系统字体，数字按需使用等宽字体。阶段轨道与组成色条承担信息表达；编号对应真实的压缩阶段。工具 JSON 放入次级开关，默认展示可读正文。

应用不调用模型，不发送会话内容，不提供停止、发消息、审批或压缩会话的操作。任务跳转通过本机 Codex URL handler 打开。系统通知默认关闭，启用后只报告明确失败和明确等待用户，不回放旧通知。

## 功能如何产生实际价值

| 场景 | 观察与判断 | 可执行动作 | 使用价值 |
| --- | --- | --- | --- |
| 同时推进多个项目 | 全量任务目录默认按整组最近活动排序，可切换需关注优先 | 筛出需要输入或失败的任务，返回 Codex 处理 | 减少逐个打开任务检查的次数 |
| 一轮执行很慢 | 查看最后事件、调用耗时、连续失败和静默提示 | 展开源结果，区分构建等待、依赖失败和反复调用 | 缩小人工排查范围 |
| 上下文接近容量 | 查看两次高占用采样、压缩阶段、工具返回内容 | 定位相关调用，减少重复输入，准备交接摘要 | 让上下文管理有证据和时机 |
| Token 增长明显 | 比较逐次请求、轮次和会话累计、缓存比例 | 检查是否反复读取相同内容，缩小输出 | 找到可以调整的输入与工具行为 |
| 多 Agent 协作 | 关联父子任务及各自状态，保留归属用量 | 打开具体子任务或返回父任务 | 避免把父任务状态当成所有子任务的状态 |

优先完成「发现异常 → 查看证据 → 返回任务处理 → 观察是否解除」的闭环。提示必须能跳到相应证据或时间段；没有充分证据的场景保留未知。首版不做自动修复、精确账单估算或 Skill 占用归因。

使用效果可用三个问题判断：是否减少了切换任务检查的次数；是否更快找到了异常调用；提示是否能够解释并促成一次具体操作。当前版本没有收集用户行为遥测，因此不声称这些效果已经量化验证。

## 数据流与职责

| 数据来源 | 用途 | 边界 |
| --- | --- | --- |
| Codex 会话索引 | 全量目录、名称、模型、effort、归档、父子关系、日志位置 | 只读；无字段时显示未知 |
| Codex 分页历史 | 最新轮次状态、按序号分页的结构化事件 | 与日志可能短暂不同步，较新的日志生命周期证据优先 |
| 会话 JSONL | 新事件、时间信息、逐次 Token、压缩与上下文采样 | 只能观察已经持久化的记录 |
| App Server | 无名称会话的可选标题补全 | 使用索引查询和分页；不 resume，不用独立进程推断全局运行状态 |
| 应用缓存 | 检查点、有限事件摘要、用量去重、提示已看状态 | 可重建；不修改 Codex 源数据 |

核心库包含目录读取、增量解析、规则和缓存。MonitorEngine 在 actor 中执行，界面只接收可发送的快照。采集器随应用运行，不随详情页销毁。

| 源码 | 职责 |
| --- | --- |
| Sources/SessionAtlasCore/ObservationModels.swift | 事件、用量、上下文与关注事项的数据定义 |
| Sources/SessionAtlasCore/ObservationStore.swift | 只读 SQLite、目录、分页、证据及应用缓存 |
| Sources/SessionAtlasCore/ObservationParser.swift | 增量 JSONL 解析、归属校验与统计归一化 |
| Sources/SessionAtlasCore/MonitorEngine.swift | 文件监听、待处理队列、快照与恢复调度 |
| Sources/SessionAtlasCore/AttentionRules.swift | 提示条件、证据、合并及解除 |
| Sources/CodexSessionAtlas/MonitorApp.swift | 窗口、刷新生命周期、设置与通知 |
| Sources/CodexSessionAtlas/WorkspaceView.swift | 目录、筛选、父子列表与证据弹窗 |
| Sources/CodexSessionAtlas/SessionDetail.swift | 概览、轨迹、待关注事项及协作关系 |
| Sources/SessionAtlasCore/ContextComposition.swift | 按需索引压缩阶段、消息材料及采样位置 |
| Sources/CodexSessionAtlas/ContextView.swift | 阶段选择、组成分类、材料正文入口 |
| Sources/CodexSessionAtlas/MonitorTheme.swift | 颜色、面板、标签及可读文案格式 |

采集调度如下：

1. 每两秒刷新目录及最新持久化轮次；初次立即返回目录，不扫描全部历史正文。
2. 使用 FSEvents 收集目录变化；已加载会话同时检查文件大小、修改时间和 inode，每十五个刷新批次补偿检查所有已知日志路径，正常情况下约三十秒。
3. 优先处理选中会话，再处理待处理队列和新变化。每批处理使用时间预算，未处理完或暂时读取失败的工作保留在队列中，不随文件通知清空。
4. 首次读取日志末段，随后只读追加字节。轨迹从分页历史每次取一百条；无分页历史时按日志区段向前读取。
5. 每个会话最多保留三百条日志事件摘要、两千个上下文／用量样本；详细状态最多驻留一百二十八个会话，其他状态从应用缓存恢复。
6. 详情点击时读取原始记录，单页最多二万四千字符。日志详情校验记录摘要，源内容变化时显示不可验证，不展示错位证据。

目录中的名称及首条消息预览限制为 256 字符，在 SQL 查询时截取；旧版索引可能将整段输入重复保存在 title 和 preview 中，不能把这些正文当作轻量元数据全量载入。完整输入仍从轨迹详情读取。

主要接口为 start/stop、poll、observation、timeline、loadEarlierContext、detail、markSeen 和 updateSettings。公开模型将 SessionSummary、TraceEvent、UsageSample、ContextSample 和 AttentionItem 分开，避免把执行状态、用量和当前占用混为一谈。

## 状态与统计口径

### 执行状态

使用未知、最近活跃、状态待确认、等待用户、本轮结束、失败、已中断七种展示状态。只根据明确生命周期记录改变结束状态，不根据静默时长判定完成或卡死。

「最近活跃」要求最近合并状态仍在执行，且最近执行记录或轮次开始时间距当前不超过 5 分钟；目录编辑时间不参与判断。超过此时间或没有时间证据时展示「状态待确认」，新执行记录到达后重新判断。最多容忍 60 秒的时钟偏差；更远的未来时间不作为活跃证据。该展示分类不改写原始日志状态。

独立观察器不能证明进程此刻仍在执行。读取失败保留上次快照、重新判断活跃时效并显示数据诊断。没有本地日志的目录项明确显示未接入。「最近活跃」筛选排除等待用户及已归档任务；为了展示子任务关系而保留的父任务明确标注「含活跃子任务」。

等待用户需要已记录的同步输入请求及尚未观察到的响应；异步问题不阻塞任务。工具失败不自动等同于轮次失败。任务目标是否完成由使用者判断。

### 用量

- 新版使用逐次响应记录，按原始归属会话及响应标识去重。分叉中复制的其他会话用量不归入新会话。
- 运行时累计值取最新快照，不累加累计快照。旧版只有累计值时，仅在连续、非负的情况下计算增量，标记为累计差值。
- 全局「监控期 Token」统计缓存建立后观测到的请求，滚动保留三十天；不是全部历史账单，也不换算订阅费用。
- 缓存输入是输入的子集，推理输出是输出的子集，均不能重复相加。
- 缓存命中率为对应输入中的缓存比例；缺少输入时显示未知。

### 上下文

采用最近一次 token_count 提供的占用及窗口容量，显示采样时刻。上下文页按压缩阶段组织曲线，并区分模型和窗口变化。压缩后没有新用量时，新阶段占用显示未知，不沿用旧值声称压缩已经节省了空间。

轨迹里的输出大小按可见文本字节数统计，不等同于模型当前保留的内容，更不代表每个 Skill 的精确 Token 占比。上下文变化和邻近工具调用仅用于定位相关证据，不宣称单一调用造成了全部变化。

概览中的占用取日志末段的最近采样。上下文组成页按需从所选任务的源文件起点建立阶段与采样索引。已截断或源文件缺失的历史不能恢复成完整轨迹。

### 各阶段具体有哪些内容

0.3.0 增加独立的按需材料索引。初始记录构成第一个阶段，每次 compacted 开始一个新阶段。若包含 replacement_history，新阶段以这份替换消息集合为基础；此前材料不直接继承。后续 response_item 逐项加入当前阶段。

可见内容分为规则与指令、技能清单、工作环境、用户输入、助手回复、调用参数、工具返回、压缩摘要、图片与附件。每项材料保存分类、标题、字符量、时间、短预览和源位置，点击后读取正文。分类按钮筛选材料，采样选择器按字节序号截取到对应记录。正文支持原始结构切换和分页。

压缩时保留的材料有明确标记。加密压缩摘要显示不可读且不计入可读字符量；不展示隐藏推理，不用旧材料冒充压缩后的内容。缺少替换集合时明确说明只知道可读摘要及之后新增的材料。

组成色条是可读字符量的比例，和运行时上报的上下文 Token 分开。它表示截至某一位置记录下来的材料，可能包含刚生成的输出；日志还可能遗漏系统提示、工具定义、服务端裁剪，因此不是完整请求输入或精确 Token 归因。

索引只在查看上下文时运行，与全目录采集分开。每批最多读取 8 MiB，保留字节游标，后续只处理追加内容；切换任务时重新建立该任务的索引。每份索引最多 20,000 项材料，超出后提示覆盖限制。正文仍从源文件按需读取，并通过记录摘要和 JSON 路径定位，不整体复制到缓存。

### 待关注规则

| 规则 | 默认条件 | 建议 |
| --- | --- | --- |
| 轮次失败 | 明确失败结束 | 查看错误及前后调用 |
| 等待输入 | 同步请求尚无响应 | 打开原任务作答 |
| 连续失败 | 相同工具、参数和结果连续三次失败 | 检查依赖或参数后再重试 |
| 重复读取 | 五分钟内三次相同、明确只读调用 | 检查是否可复用结果；排除已识别轮询 |
| 上下文偏高 | 两次有效采样达到 85% | 定位大内容，降至 75% 以下解除 |
| 大输出 | 单次可见输出达到 128 KiB | 过滤、聚合或分页 |
| 无新事件 | 未结束轮次静默十分钟 | 人工查看最后操作，不判定卡死 |

规则提供事实／提示标记、源证据、建议、已看及解除状态。同一问题合并展示。调整阈值后在下次刷新生效。

## 恢复、兼容与验证

SQLite 只读连接使用短事务并兼容 WAL。应用缓存中的游标、状态与本批用量在同一事务提交。缓存格式不兼容时重新读取源记录，用量账本仍通过响应标识去重。

历史库短暂读取失败时保留最近一次成功的轮次状态，日志仍继续采集；较新的数据库完成记录优先于较旧的日志开始记录，避免状态倒退。诊断只展示错误类别和 SQLite 错误码。

重启时将已有检查点的会话重新加入补读队列，包括未选中的冷会话；不依赖该会话刚好出现在当前页面。

JSONL 末尾未完成的一行留待下次处理。文件截断或替换时重新定位，并标明恢复边界。无法解析的记录不会阻断后续完整记录。单条超过 32 MiB 且没有记录边界时停止该段读取，显示限制；不伪装成完整采集。

实时性从记录落盘开始计算。未落盘的流式片段、未持久化会话、远程与云端任务，以及不兼容或压缩后不可直接读取的日志，不在首版完整实时覆盖承诺内。

验证使用现有 FixtureChecks、新增 ObservationChecks 和只输出计数的 MonitorProbe。测试覆盖大目录、增量发现、半行、去重、分叉、压缩、等待、失败、规则、分页和读取中断。界面与安装包另做实际启动、源记录展开、上下文查看、签名及压缩包校验。
