# 使用手册

[English](usage.md) · [README](../README.zh-CN.md) · [安装手册](installation.zh-CN.md)

## 先确定想回答的问题

用「概览」发现值得检查的事项，用「轨迹」查看执行过程，用「上下文」查看已记录材料，用「协作」跟进子任务。Session Atlas 提供已落盘的证据；实际修改仍在 Codex 或项目中完成。

## 查找任务与理解排序

搜索匹配任务标题、项目路径、模型、Agent 昵称或任务标识。项目菜单可缩小范围。列表右上角菜单提供系统任务、归档任务和排序选项。

- **最近活动（默认）：** 从新到旧排列。父任务取筛选范围内整组子孙任务的最新活动时间，收起子任务后也会计算。列表显示时间与排序使用同一个值。
- **需关注优先：** 存在未看、未解除事项的任务组排在前面，组间再按最近活动排序。子任务的关注事项也计入所在组。
- 单个任务取最近执行事件与轮次开始时间中的较新值；两者都未知时，暂用目录时间。时间相同时，以稳定任务标识决定顺序。
- 整组聚合范围是当前筛选或搜索结果，以及为展示关系补入的祖先任务。因此，改变筛选条件可能改变组时间。
- 为保留活跃子任务归属而补入的父任务显示「含活跃子任务」，不代表父任务本身正在执行。

排序方式会保留。默认情况下，橙色关注点不会再把历史任务顶到最新任务前面。

## 状态应该怎样理解

| 状态 | 含义 |
| --- | --- |
| 最近活跃 | 轮次未结束，近 5 分钟有执行或开始记录；活跃筛选排除归档任务 |
| 等待用户 | 记录表明在等待输入，应返回原任务处理 |
| 状态待确认 | 最后状态是运行中，但缺少近期执行证据 |
| 本轮结束 | 本轮已结束，整个用户目标不一定完成 |
| 失败 / 已中断 | 已记录的轮次级结果 |
| 未知 | 缺少足够且兼容的数据 |

工具失败后可能在同一任务中重试成功，一次工具失败不等于整个任务失败。长命令没有输出时也可能显示「状态待确认」，不能仅凭该状态判断任务已经停止。

## 概览：确定下一步看哪里

概览显示最近动作、上下文使用率、需关注事项与最近记录。处理提示前，先打开依据。

「我已看过」只改变监控器本地的关注状态，不会修复或修改原任务。「显示已解除」可以查看规则已不再认为有效的事项。

## 轨迹：沿执行过程找证据

1. 按输入、回复、工具、修改、轮次等类型筛选。
2. 使用摘要搜索或失败筛选。加载条数、分类数量和匹配数量均只针对**已加载记录**，不是所有历史。
3. 根据问题按时间、输出体积或已知耗时排序。
4. 点击记录查看可读正文，通过来源信息定位本地证据；需要时再切换原始结构。
5. 需要更早记录或更长正文时，再加载历史或详情下一页。首屏展示数量有上限，避免大量内容影响操作。

「轮次」筛选的是开始、结束等生命周期事件，并不是将整段对话按轮次重新展开。「可见推理摘要」仅展示日志已有摘要，不是模型隐藏推理。

## 上下文：依次选择阶段、采样和材料

1. 选择「首次压缩前」或「第 N 次压缩后」。不要把前一阶段的材料当成下一阶段仍然保留的内容。
2. 点击曲线或前后采样按钮选择时间点，结合时间戳读取数值。
3. 查看「上下文使用率」：采样中的已用 Token 除以已知容量。
4. 查看「已记录内容的文本占比」：颜色表示材料类别，长度比较的是可读字符量，不是精确 Token。
5. 选择类别，查看最长内容，或查看两次采样间新增的材料。点击整行打开正文及来源。

只有同阶段、同模型、同已知容量的相邻采样才比较 Token 差值。两个位置之间的材料说明当时记录了什么，不能直接证明精确 Token 因果关系。「压缩时保留」以实际记录的替换消息集合为依据；缺少替换数据时保留未知。

| 分类 | 具体是什么 | 不能据此得出的结论 |
| --- | --- | --- |
| 规则与指令 | 可见的行为要求、项目约定、权限和记忆使用说明 | 已拿到完整隐藏系统提示 |
| 可用技能说明 | Skill 简介和调用条件 | 列出的技能都已加载或执行 |
| 运行环境信息 | 工作目录、时间、运行环境与插件描述 | 环境健康或配置正确 |
| 用户输入 | 用户请求及补充说明 | 已覆盖未记录的界面状态 |
| Agent 回复与进展 | 已记录的回答和进展正文 | 包含工具调用参数 |
| 工具调用内容 | 命令、搜索词、修改内容等工具输入 | 代表工具的实际返回 |
| 工具返回 | 文件正文、检索结果、命令输出和报错；通过工具读取的 Skill 文档也在这里 | 模型目前仍保留这些全部内容 |
| 压缩摘要 | 已记录的摘要，或摘要不可读的标记 | 可以解密不透明摘要 |
| 图片与附件 | 日志可见的附件信息 | 可以精确计算图片或附件 Token |

## 示例：分析一次上下文增长

假设两个可比较的采样分别为 40K 和 70K Token。这里是说明方法的示例，不是实际测量结果。

1. 选择后一个采样，查看相对前一个采样新增的材料。
2. 如果有较大的工具返回，打开正文，确认是否包含完整文件、重复检索结果或大量日志。
3. 在轨迹中定位对应调用，查看原命令。下次执行可以尝试更窄的查询、限制输出范围或只读取相关文件片段。
4. 在相似任务中再次观察工具输出与上下文采样，比较变化。

不能直接说该工具返回「正好消耗了 30K Token」，因为其他输入和模型请求构造也可能参与变化。同样，「可用技能说明」很大只说明值得检查技能目录文字，不代表某个 Skill 实际执行了，也不自动等于浪费。

## 协作与设置

协作页关联父子任务，分别显示各自状态和上下文采样。应进入具体子任务检查依据，再返回 Codex 处理。父子任务拥有各自的上下文容量，不能直接相加百分比。

左侧设置按钮可以调整重复次数与观察窗口、高占用阈值、大输出阈值、静默时间和系统通知。通知默认关闭；启用后只对新发生且明确的失败、等待输入事件发送通知，不会将所有推测性提示都变为通知。

关闭窗口后继续观察，可从 Dock 重新打开。退出应用停止采集，下次启动从检查点继续。目录刷新目标约为 2 秒，排队读取与冷会话核对可能更晚完成；这是对已落盘数据的观察，不保证端到端延迟始终为 2 秒。
